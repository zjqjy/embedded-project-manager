# STYLE.md — 讲解与笔记的风格规范（硬规则）

> 适用范围：learning 插件产出的所有讲解类文档（README 卡片 / deep-dive / 口播稿 / 图解文字）。
> 目标：读者是人，不是评审 AI。写完自检：**只用行业术语 + 至多一个类比，结论先行，标题即重点。**

## 一、词汇规则（违反 = 重写）

1. **用行业术语本身当主语。** I2S、BCLK、采样率、DMA、flush 回调——直接用，首现时括号一句白话即可。
   - 正例：`BCLK（位时钟，每拍传 1 个 bit）`
2. **禁止给概念起拟人代号或自造名词。** 包括但不限于：画家、翻译官、快递员、管家、司机、肥猫、喂料台、换班哨、传送带、管子、打字机模型、三件套。
   - 反例：`MAX98357 是个从不出门的翻译官，你把暗号递给它…`
   - 正例：`MAX98357 = 16bit DAC + D 类功放。它自动识别 I2S 时钟，无需寄存器配置：供电、给时钟、给数据，就出声。`
3. **类比最多 1 个/篇**，必须一句话带过（"就像…"），不得发展成角色、剧情或贯穿全文的设定。图解里同样禁止出现自造角色名。

## 二、结构规则

4. **一篇只回答一个主线问题。** 开头第一段直接回答它；与主线无关但正确的内容删掉。
5. **结论先行。** 全文前 3 行必须让读者明白整个机制；每节第一句是该节结论。
6. **标题即结论。** 用判断句，不用名词短语。读者只读标题就能复述全文逻辑。
   - 反例：`## I2S 三根线`
   - 正例：`## I2S 用三根线传采样：BCLK 定节拍，LRCK 分左右声道，DIN 走数据`
7. **参数集中。** 数字、引脚、配置用表格放一处，不在叙述里撒。
8. **坑写成表。** 症状 → 原因 → 处理，三列，一行一坑。

## 三、语气规则（去 AI 腔）

9. 无 emoji 轰炸（每篇 ≤2 个，仅限标题）；无加粗轰炸（每节 ≤1 处）。
10. 禁用：让我们、值得注意的是、总的来说、综上、不难发现、感兴趣的小伙伴。
11. 不用排比句和感叹号；不说"恭喜/太棒了"。
12. 图表数量默认 ≤3 张/篇；每张图必须被正文引用并解释一个且仅一个概念。
13. 文档尾部不放 AI 元数据（如 "AI Self-Score"）；保留 LPR 阶段与日期即可。

## 四、讲解类笔记的标准骨架

```
1. 结论        —— 3 行内说完整个机制
2. 数据流      —— 一张图 + 每站一行
3. 关键参数    —— 表格
4. 常见坑      —— 表格（症状/原因/处理）
5. 自测        —— 3~5 问，能答出 = 懂
```

> 自检方法：把文档给没看过对话的人读 3 分钟，让他复述机制。复述不出 = 违反了上面某条。

## 五、定稿工序

成稿后按 [HUMANIZE.md](HUMANIZE.md) 清单过一遍 AI 痕迹（命令：`/em learn humanize <slug>`），五维评分 ≥45/50 才算定稿。
