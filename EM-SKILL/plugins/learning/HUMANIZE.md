# HUMANIZE.md — 去 AI 味检查清单（成稿必过）

> 用途：任何讲解类产物定稿前的最后一道工序（`/em learn humanize <slug>`，或手动逐条过）。
> 方法来源：[humanizer-zh 技能](https://github.com/blader/humanizer)（译自 Wikipedia:Signs of AI writing，WikiProject AI Cleanup 维护）。
> 与 STYLE.md 的分工：STYLE.md 管"怎么写才对"（术语/结构），本清单管"写完有没有 AI 痕迹"。

## 七类模式与改法

### 1. 夸大与宣传
**触发词**：标志着、见证了、至关重要、关键作用、不可或缺、里程碑、彰显、凸显、坐落于、令人叹为观止、充满活力、丰富的（比喻义）、开创性、激动人心的时代、未来可期
**改法**：删形容词，只留事实和数据。
- 反：`这一步标志着驱动开发的重大里程碑，彰显了分层架构的强大威力。`
- 正：`这一步完成后，屏幕可以出图了。`

### 2. 肤浅分析尾缀
**触发词**：句尾的"，确保…、，彰显…、，反映…、，促进…、，为…奠定基础"
**改法**：整句删掉尾缀；要解释因果就给具体机制，不给空洞升华。

### 3. 模糊归因与免责声明
**触发词**：专家认为、行业报告显示、据了解、有观点指出、截至（训练日期）、基于可用信息
**改法**：换成具体来源（数据手册第几页 / 实测记录），没有来源就删。

### 4. AI 高频词与绕弯句
**触发词**：此外、深入探讨、赋能、格局、织锦、宝贵的、复杂性、相互作用、不可或缺
**系动词回避**："作为/充当/扮演着…角色" → 直接用"是"。
**同义词循环**：同一个东西每次换称呼（主控/CPU 芯片/处理器乱换）→ 全文统一一个名字。
**虚假范围**："从 X 到 Y"但 X/Y 不构成真实刻度 → 改成平实列举。

### 5. 公式化结构
- **否定式排比**："不仅…更…""这不是…而是…" → 直接陈述。
- **三段式强迫症**：什么都凑三条 → 改两条或四条（该几条是几条）。
- **模板节**："挑战与展望""未来可期"式的凑数章节 → 删。
- **对话痕迹**："当然！""好的！""希望对您有帮助""请告诉我" → 删。

### 6. 格式痕迹
- **破折号轰炸**：一段两三个"——" → 改逗号或拆句。
- **粗体轰炸**：每节一堆加粗 → 每节最多 1 处（STYLE.md 同款规则）。
- **伪列表**：`- **标题：** 一句话` 的机械列表 → 能连成句就连成句。
- **emoji 装饰**：🚀💡✅ 开头 → 删（模板要求的节标记除外）。

### 7. 填充与谄媚
- 填充短语：在这个时间点→现在；由于…的事实→因为；值得注意的是→删；为了实现这一目标→为此。
- 过度限定："可能潜在地或许大概会影响" → "可能影响"。
- 谄媚开头："好问题！" → 删。

## 交付前快速清单

- 连续三句等长？打断一句
- 段落都以一句金句收尾？换掉结尾
- 破折号后才出现重点？重排语序
- 在解释一个显而易见的比喻？删解释
- 出现"此外/然而"开头？试试直接删
- 列举恰好三条？数一数是不是硬凑的

## 处理流程

1. 逐节扫描，标出七类模式的实例
2. 重写问题片段：保持含义、保持技术准确性、代码和参数原样不动
3. 出声读一遍：卡壳的地方就是还有 AI 味的地方
4. 评分（1-10 × 5 维，≥45 通过）：直接性 / 节奏变化 / 信任读者 / 听感真实 / 无冗余
5. 输出改动清单（模式 → 位置 → 改法）

## 技术文档补充说明

- 术语表、参数表、坑表**不受**"三段式/列表"规则限制——表格是技术文档的正装。
- 代码示例与命令行**永远不动**。
- 首术语白话注释（如 `BCLK（位时钟）`）不算 AI 味，是 STYLE.md 要求的写法。
