# 命令: /em ask (知识提取)

## 功能
从 vault 检索知识回答问题——返回带路径+双链的片段，命中快捕卡自动累积 surfaced 信号（转正判定的输入，宪法 §9.3）。

## 触发
```
/em ask <问题>
```

## 前置
未配置库时**不要只甩报错**：按 `commands/vault.md` §init 引导用户二选一（选目录建库 / 装 Obsidian 指引），建好再继续本次提问；用户明确说「以后」才中止。

## 执行流程（AI 中介检索，S21-E）

1. **【拆词】** AI 先把问题拆成 **3-6 组检索变体**：原文关键词、英文译名/技术词、同义表述、上位词。
   例：问"音源导入失败" → `音源` + expand `jsDelivr, GitHub raw, LX music, 导入超时`
2. **【检索】** 一次命令带全部变体（本地逐组计分，多变体独立命中的卡加分排序，surfaced 只回写一次）：
   ```bash
   python "<SKILL_DIR>/tools/vault/search.py" query "<主查询>" --expand "变体2,变体3,变体4" --limit 5 --surface-top 3
   ```
   纯本地关键词/二元组计分（标题×3、tags×2、正文×1），无索引服务、无向量库。
3. **【复筛】** AI 读返回 JSON：丢掉只靠低分二元组碰巧命中的弱相关项，按真实相关度排序；snippet 不够时 Read 原文件。
4. **【回答】** 回答必须带出处：`[[笔记名]]`（相对路径），快捕卡注明「尚未转正」。
5. **【缺口】** 复筛后为零 → 换一组变体再试一轮；仍为零 → 明说"库里没有"，提示 `入一下库` 可存本次结论。

## briefing 模式

`/em vault briefing` 或 `/em rec` 附带：近 7 天入库摘要 + 待确认数（`search.py briefing`）。

## 输出格式
```
🔍 /em ask — <问题>
- <结论要点> — [[来源笔记]]（<路径>）
...
✍️ surfaced 已回写 3 张
```
