# 工作流: R0 需求澄清（追问轮）— 三档共用

> 适用：`/em new` 三档全部（轻/中/重），在档位选定后、任何方案/计划输出之前执行。
> S18 依据调研改造（`docs/research/2026-10-10-clarify-before-write.md`）：
> github/spec-kit `/clarify` + obra/superpowers `brainstorming` 的共识——
> **AI 不断追问人类 → 理解经用户确认 → 最后一步才写文档。**

## 硬闸门（HARD-GATE）

需求理解摘要未经用户确认之前，**禁止**：

- ❌ 输出任何完整方案 / 计划 / 拆分草稿（哪怕「先草拟一个供参考」也不行）
- ❌ 创建或写入 `<STATE_DIR>` 下任何文件
- ❌ 开始编码

「描述很简单」不是跳过确认的理由——轻档也必须过理解摘要这一关（摘要可以短到两三句话）。

## 追问下限与退出条件（S18.1 按用户反馈修订）

**不设问题上限**——追问轮的退出条件不是问够某个数字，而是 **AI 判断用户意图已经清晰**：
目标、边界（不做的事）、验证方式都能各自一句话说清、无关键歧义。真正的门是理解摘要的用户确认。

最少提问数（防止 AI 不问就开写；可按项目约定调整）：

| 档位 | 至少问 | 说明 |
|------|--------|------|
| 轻 | ≥ 1 | 无真歧义时用「确认题」满足（见最简确认路径） |
| 中 | ≥ 2 | 优先影响架构/验证/边界的问题 |
| 重 | 每子系统 ≥ 1 | 由 discussion-flow 阶段2 按子系统逐个追问 |

- 问满下限后：仍有关键歧义 → **继续问，不设上限**；意图已清晰 → 输出理解摘要。
- 单题的澄清复述（「你是指 A 还是 B？」）不计入下限。
- 用户说「别问了 / 就这样 / 开始吧」→ 立即停止追问（**唯一可低于下限的方式**），把已答内容整理进理解摘要。

## 提问规则

1. **一次只问一个问题**——不打包多问，不预告后面的题。
2. **能选择题就不开放题**：2-5 个互斥选项，推荐项放首位并给理由；都不合适时用户可自由作答。
3. 每问附一句「为什么问」，让用户判断值不值得答。
4. **只问高影响问题**：影响目标、边界、验证方式、硬件/外部约束的才问；实现细节（用什么库、什么函数）不问。
5. 没有真歧义时不硬凑开放题——用一道「确认题」满足下限（见最简确认路径）。
6. 用户反问上下文时：先回答用户的疑问，**当前问题保持挂着**，答完重新抛出。

## 提问格式（对话内，每条消息一问）

```
❓ R0-<n>: <完整的问题>？
   为什么问：<一句话>
   | 选项 | 说明 |
   |------|------|
   | ⭐ A. <推荐项> | <理由> |
   | B. <…> | <…> |
   ━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   回复选项字母，或直接描述。
```

## 最简确认路径（没有真歧义时）

无可追问的关键歧义时，下限用一道**确认题**满足——把理解里最关键的一个判断交给用户选（优先验证方式或边界）：

```
❓ R0-1: 验证方式按 <X> 来可以吗？
   为什么问：确认完成标准的理解一致
   | 选项 | 说明 |
   |------|------|
   | ⭐ A. 是，按 <X> 验证 | <理由> |
   | B. 按 <Y> 验证 | <…> |
   ━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   回复选项字母，或直接描述。
```

答完后仍须输出完整理解摘要并获确认，不因走捷径而跳过。

## 追问结束 → 需求理解摘要（必经，不可跳过）

问满下限、且 AI 判断意图清晰（或用户叫停追问）后，AI 输出**需求理解摘要**：

```
📋 R0 需求理解摘要（S<N>-<slug>）
- 目标：…
- 背景/现状：…
- 边界（不做的事）：…
- 验证方式：…
- 已确认的约束：
  - Q: <追问1> → A: <答案1>
  - Q: <追问2> → A: <答案2>
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
✅ 输入 `确认` → 进入 <对应档位的下一阶段>
✏️ 有偏差直接说，修正后再确认
❌ 输入 `取消` 退出
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

- 用户确认前**不进入下一阶段**；确认后由对应档位工作流接管。
- R0 的 Q→A 记录**此时不落盘**——中档由 R3 并入 plan.md 方案章「需求理解」；轻档留在对话（本来零文件）；重档并入 requirements.md。
