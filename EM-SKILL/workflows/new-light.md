# 工作流: new 轻档（quick）

> 适用：< 2h 工作量、单文件改动、bugfix、参数调优、小特性
> 产出：**0 个文件**（S17-A 起轻档不落盘——计划留在对话里，验证通过后由 `/em result` 在会话日志记一行）

## 核心理念
**最小可执行计划**：不发散、不头脑风暴、只确认目标和边界 → 直接 verify。
**不落盘原则**（S17-A）：轻档需求的价值在快速执行，不在留档；quick-plan 草稿只出现在对话中，避免 discussion/ 目录被一次性小改动灌满。

## 流程

```
1. AI 在对话中输出 quick-plan 草稿（基于功能描述）
   ↓
2. 用户「继续」或修改
   ↓
3. 直接开始编码（不保存 quick-plan.md）
   ↓
4. 更新 state.md（当前步骤 + 下一步动作）
   ↓
5. 提示 /em verify s<N> 进入验证
   ↓
6. /em result 通过时，会话日志记一行计划摘要（唯一的留痕）
```

## 步骤 1: AI 输出 quick-plan 草稿（对话内，不落盘）

**模板**:

```markdown
# quick-plan: S<N>-<slug>

## 一句话目标
<10-30 字以内，描述完成后世界变成什么样>

## 改动清单（≤ 5 项）
- [ ] 文件1 - 改动摘要
- [ ] 文件2 - 改动摘要

## 验证方式
<如何确认完成了：跑某测试 / 启动看现象 / 用户口述>

## 不做的事（边界）
- 不重构无关代码
- 不引入新依赖
```

输出后提示：
```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
✅ 输入 `继续` 采用此计划（不落盘，直接开工）
✏️  或直接修改任意字段
💾 输入 `留档` 将 quick-plan.md 保存到 discussion/（默认不保存）
🔄 输入 `升档 中` / `升档 重` 切换档位
❌ 输入 `取消` 退出
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

> **留档是例外**：仅当用户明确说「留档」（或需求有复用/追溯价值）时，才保存
> `<STATE_DIR>/discussion/<YYYYMMDD>-<slug>/quick-plan.md`。

## 步骤 2: 同步状态

- `state.md` 更新（不存在则从模板创建，S17-A 首次写入原则）：
  - 当前步骤 = S<N>（开发中）
  - 下一步动作 = `/em verify s<N>`
- `project-spec.md` 步骤表：轻档**不追加**（避免小改动膨胀步骤表）；步骤号照常占用，verify 通过后由 result 补记一行

## 步骤 3: 收尾输出

```
🎉 S<N> 计划确认（轻档，未落盘）

📝 改动清单: <N> 项
✅ 验证方式: <一句话>

━━━━━━━━━━━━━━━━━━━━━━━━━━━━
下一步:
  开始编码 → 完成后 /em verify s<N>
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 边界 / 升档触发

如在轻档中发现：
- 改动 > 5 个文件
- 跨多个子系统
- 涉及硬件外设新接入

→ AI 主动提示：「此需求可能超出轻档范围，建议升档为中档（`/em new ... --std`）」
